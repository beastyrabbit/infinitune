## Serving and verification handoff

`apps/web/src/server.ts` rejects structural path aliases with 400 before `getLegalResponse`, app rendering or request spans. It reads srvx's original Node URI, falling back to `Request.url`, and inspects only the path before a query or fragment. Encoded slashes, backslashes, percent signs and dots, literal backslashes, and exact `.` / `..` segments are rejected. Decoding therefore cannot create separators or dot segments at any level. The remaining aliases use one decoding pass and drop empty slash segments, matching the edge for the four public legal paths. Canonical paths, `/privacy/`, `//privacy` and `/privac%79` serve static HTML directly; query strings containing encoded URLs remain valid. Matching stays case-sensitive. GET/HEAD, 405 responses and security headers are preserved. Each page is self-contained HTML with inline CSS, no scripts/API/fonts/external assets, noindex metadata/header and restrictive CSP. nginx already routes them to the frontend. The shared legal footer remains in the root document shell; settings adds bottom padding to clear the fixed save bar, and the embedded mini player is excluded.

Unit coverage checks all four rendered pages for operator details, per-site addresses, the slugged contact URL, no draft markers/unresolved placeholders, no excluded backup provider, matched language sections and no unused recipients. Production-build browser tests cover home/footer navigation and standalone JavaScript-disabled pages at 1280px and 390px. Provider/telemetry calls are mocked or blocked.
